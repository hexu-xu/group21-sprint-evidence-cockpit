# 爱管理 Sprint 3 候选发布说明

**状态：候选，尚未获得团队人工发布批准；最终 Release Tag 待定。**本文件的功能描述对应当前候选分支，合并与发布前需根据最终提交、测试和人工检查结果复核。

## 本轮可验证的变更

- D1：任务看板继续展示任务总数、已完成数和进行中数；成员看到的数字现明确标为“分配给我的任务”，项目经理看到的数字代表当前项目。
- D2：新增项目概览中的三态数量与占比分布；状态变化后按当前数据重新计算。
- D5：项目整体概览除任务完成率、未完成数、逾期数和下一截止日外，支持由项目经理记录累计故事数的计划检查点、实际结果及证据，并显示最近已到期检查点的差额。
- 权限：概览限项目经理、平台管理员和只读管理员访问；普通成员和无项目权限者不能查看。
- 技术债：新增 GitHub Actions 测试工作流配置和可重复执行的浏览器旅程脚本。在线 CI 结果、最终版本浏览器记录及技术债处置仍待核验。

## 累计功能边界

Sprint 1 的 U6 岗位内容和服务端权限隔离、Sprint 2 的 T1～T5 与 T7 任务协作路径仍在代码中。Sprint 3 的 D1/D2/D5 是否达到正式 DoD，须由全量回归、端到端验证和人工审查决定。D3、D4、D6、U1～U5、U7、T6、T8 不在本轮承诺范围；统计卡中的逾期数量不等于 D4 的逾期或长期未更新任务列表已经完成。

## 已知限制和待办

- 故事进度比较需要项目经理录入真实的计划基线与到期实际值；系统不会把任务数冒充故事数，也不会在缺少实际记录时推断是否达标。比较结果不代替质量和发布决策。
- 浏览器旅程脚本需在一次性演示数据库中单独运行，尚未接入 CI；最终 Release Tag 上仍需保存实际操作证据。
- 项目及用户管理、备注、复杂筛选和趋势分析仍待后续实现。
- 发布清单的人工签认、最终主干测试、在线 CI 记录、演示材料和 Release Tag 尚待完成。
