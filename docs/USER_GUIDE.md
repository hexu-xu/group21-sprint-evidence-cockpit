# 爱管理用户手册

## 适用范围

本手册说明在 Sprint 3 主干基础上新增的故事地图待办能力。项目及演示账号由 README 中的初始化命令创建；管理员可新增用户和命名角色，但用户不能自助注册，项目创建界面尚未开放。本分支的最终发布范围以代码审查和新的发布决定为准。

## 登录与角色

启动方式和演示账号见仓库根目录 README。演示密码由本机 `DEMO_PASSWORD` 设置，不随源码分发。

| 身份 | 可用操作 |
| --- | --- |
| `manager` 项目经理 | 创建和分配任务、查看本项目任务/成员角色/概览/待关注任务/统计分析/进度趋势、更新状态、调整模块、确认删除 |
| `member`、`member2` 项目成员 | 查看分配给自己的任务，更新状态并写进展备注；不能查看整体概览或他人任务 |
| `observer` 只读管理员 | 查看项目任务及整体分析；不能创建、修改、删除任务或写备注 |
| `admin` 平台管理员 | 管理用户和角色，查看和维护项目任务及整体分析 |

## 完成一次任务协作

1. 以 `manager` 登录，在“创建任务”填写标题、描述、所属模块、优先级、截止日期和负责人。
2. 在任务看板确认任务卡、负责人和状态；切换“待完成／进行中／已完成”标签查看各状态。
3. 切换为被分配的成员账号，打开自己的任务详情，把状态改为“进行中”或“已完成”。
4. 切回 `manager`，在任务看板和“项目概览”确认状态、完成数和状态占比同步变化。
5. 如需核对权限，切换为另一位成员，确认无法看到或修改不属于自己的任务；`observer` 可以查看概览，但不能提交修改。
6. 管理员可在“用户与角色”创建命名角色、选择固定权限模板，再创建用户并加入现有项目；可以为用户修改或移除命名角色及停用账号。项目经理可在“项目成员”查看当前项目人员与角色。
7. 在任务看板按名称、优先级、负责人、截止日期和状态筛选；成员可在自己的任务详情写进展备注。项目经理打开“待关注任务”核对逾期或超过指定天数未更新的任务，打开“统计分析”查看截止日期范围内的状态数量，打开“项目进度趋势”比较检查点累计计划与已登记实际。

## 理解项目概览

“任务总数”“已完成”“进行中”“待完成”只统计当前选中的项目，三种状态数之和等于任务总数。完成率为已完成数除以任务总数；无任务时显示 0%。状态分布展示每种状态的数量和占比。

“已逾期”只统计尚未完成且截止日期早于今天的任务。“下一截止日期”是当前未完成任务中不早于今天的最早截止日。它们是任务级提示，与下面的故事进度检查点分别统计。

## 记录故事进度基线与实际结果

项目经理或平台管理员在“项目概览”中新增检查点，填写检查日期、计划累计完成的用户故事数、**基线版本和真实编制日期**。例如，本轮 v1 基线于 2026-10-20 编制，采用 2026-10-18 已验收的 7 项作为起点；不能把起点日期写成计划编制日期。检查点按日期排列，累计计划数不能倒退。到期并有实际验收证据后，再填写实际累计故事数和证据位置；未来检查点的实际数保持空白。

修改已有检查点时须填写修订原因。修改检查日期或计划目标还须改用新的基线版本；实际数或证据更正也须填写原因。页面展示每次修改前后的目标、实际、证据、版本、编制日期、操作人和时间，旧值留在修订记录中。迁移前已存在的检查点若缺少历史元数据会显示“待核”，更早的修改历史不能自动恢复，应先核对书面材料再补录。系统记录修订，不自动证明修订已获团队批准。

页面以最近一个已到期检查点比较计划与实际，显示达标、超前或落后及差额；缺少实际记录时显示“待登记”，不推测结果。项目任务的完成数量不会自动折算为用户故事完成数量。普通成员不能查看或修改整体概览；只读管理员可查看，但不能修改检查点。

这一比较反映检查点上的累计交付数量，不等于项目排期、质量或发布决定已由系统自动判定。

## 常见限制

- 尚无自助注册和项目创建界面。命名角色使用固定的权限模板，不支持任意配置细粒度权限。
- 进度趋势依赖人工登记的检查点；未登记的实际值保持空白。久未更新以任务最近更新时间为准。
- 切换账号需要在登录页重新输入演示密码。
- 演示数据库与密码由运行者在本地维护；不要把个人真实密码填入演示环境。
