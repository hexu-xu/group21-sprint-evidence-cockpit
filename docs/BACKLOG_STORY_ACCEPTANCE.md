# 故事地图待办功能验收记录

本记录对应 `codex/complete-backlog-stories` 分支。以《爱管理_用户故事地图_Excel.xlsx》中的原始故事文字为验收范围；不改变此前 Sprint 3 Release Tag。下列结论为开发者在本分支的本地功能验收，团队合并与发布结论另行记录。

| 故事 | 用户操作与预期 | 本地验证 |
| --- | --- | --- |
| U1 | 管理员新增用户，账号进入平台和指定项目 | 浏览器创建用户；HTTP 测试检查用户及项目成员记录 |
| U2 | 管理员查看当前用户列表 | 浏览器与 HTTP 检查新增用户可见；非管理员 403 |
| U3 | 管理员创建区分职责的命名角色 | 浏览器创建角色并选固定权限模板；重复名称拒绝 |
| U4 | 管理员为用户分配角色以限定权限 | 用户创建及角色分配后检查实际权限值 |
| U5 | 管理员修改或移除用户角色 | HTTP 测试更新并检查降为普通权限；不能改自己的角色 |
| U7 | 项目经理查看本项目成员及角色 | 浏览器和 HTTP 验证；其他项目及普通成员 403 |
| T6 | 成员记录任务进展备注 | 浏览器添加备注，检查作者与内容；越权写入 403 |
| T8 | 项目经理按状态、日期等条件筛选任务 | HTTP 验证组合条件、非法日期、成员隔离 |
| D3 | 项目经理查看项目进度趋势 | 检查点按日期显示计划/实际；未登记实际保留空白；成员 403 |
| D4 | 项目经理查看逾期或长期未更新任务 | HTTP 验证逾期、超过 7 天未更新、已完成排除和项目隔离 |
| D6 | 项目经理按时间和状态查看统计 | HTTP 验证日期范围内三态数量和按日期分组，非法范围 400 |

## 实际验证

- `python -m pytest -q`：100 项通过，包含新增 8 项故事验收测试和原有 92 项回归。
- 从旧版迁移结构与 5 个演示账号升级：`flask db upgrade` 成功，旧用户保留，新角色表与备注表可查询。
- 使用本机 Edge 对一次性数据库运行 `tests/browser_journeys.py` 和 `tests/browser_backlog_journeys.py`：主流程、权限流程以及新增角色/用户、成员视图、进度备注与趋势页面通过；截图和 JSON 位于本机忽略的 `instance/backlog-browser-evidence/`。
- `python -m pip install -r requirements-browser.txt` 与 `python -m pip check` 通过；修正了 Playwright 可选依赖冲突。

## 边界

- 命名角色选择固定权限模板；项目经理身份来自项目成员记录。细粒度自定义授权与自助注册不在故事地图要求内。
- D3 与 D5 共用人工登记的故事检查点，缺少实际数时不推断完成。D6 的时间维度定义为任务截止日期。
- 本地测试与浏览器验证支持开发者验收；独立代码复核、GitHub CI、合并和新版本发布需以各自真实记录确认。
